# Big Data - Week 6 Assignment

## Overview

This assignment uses Google Cloud Dataproc and SparkSQL to analyze transactional and customer data stored in Google Cloud Storage (GCS).
The goal is to perform key analytical queries and demonstrate Slowly Changing Dimension (SCD) handling — both Type I and Type II — using only SparkSQL.

The job reads input data from GCS, performs aggregations, applies SCD logic, and writes all results back to GCS.

## Datasets

1. `transactions.csv` - Customer transaction details

2. `customers_master.csv` - Initial customer master data

3. `customer_updates.csv` - Incremental updates to customer information

## SCD Logic

### Type I

- Filter only current (current_flag = 1) records.
- Perform a LEFT JOIN between updates and master to include any new customers as well.
- Uses COALESCE() to preserve or initialize effective_date.
- Combine updated and unaffected records into the final master.

### Type II

- Identify active records with updates and mark them expired (current_flag = 0, expiry_date = change_date).
- Insert new active rows for all updates (including new customers) with current_flag = 1.
- Preserve unaffected records as-is.
- Combine all three sets using UNION ALL for a full historical view.

## Files in this Submission

### 1. `w6_script.py`

The main SparkSQL script that performs all the analysis and SCD transformations.

**What it does:**  

- Loads three input datasets — transactions, customer master, and customer updates — from GCS.

- Runs three aggregation queries:
    1. Top 5 customers by total transaction amount
    2. Number of customers per city
    3. Average transaction value overall

- Implements SCD Type I (overwrite) and SCD Type II (historical) logic using only SQL views and queries.
- Writes all intermediate and final outputs back to GCS as CSV files.
- Logs and displays preview results in the driver output for validation.

### Output Files

All outputs were written to gs://ob-bigdata/w6/output/, with each logical result stored in its own subdirectory.
Each subdirectory contains one or more part CSV files (since .coalesce(1) was not used) and a _SUCCESS file generated by Spark.

**Subdirectories inside `./output/`**

- `top5_customers/` - Top 5 customers by total transaction amount

- `customers_per_city/` - Number of active customers per city

- `average_transaction_value/` - Single-row CSV containing overall average transaction amount

- `customer_master_scd1_final/` - Final SCD Type I master — current state after overwrites

- `customer_master_scd2_final/` - Final SCD Type II master — full historical version with active and expired rows

## Pipeline

1. **Upload**: Upload all three CSV files to the GCS bucket. Change the path in the python script accordingly.

2. **Run the Spark Job**: Run the script (`w6_script.py`) on a Google Cloud Dataproc cluster. The job automatically reads from GCS, processes data, and writes back results.

3. **Processing steps**:

    - Create temporary SQL views for all datasets.
    - Execute SQL aggregation queries.
    - Apply SCD Type I and II transformations:
        - Type I: Overwrite existing records with updates (no history).
        - Type II: Expire old records and insert new active ones (retain history).

4. **Output**: All query and SCD results are stored in GCS as separate CSV outputs.
